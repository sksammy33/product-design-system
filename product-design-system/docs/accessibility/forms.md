# Forms

Future fields need persistent, programmatically associated labels, clear instructions, and associated help/error text. Placeholder text alone is insufficient. Required and invalid states must be understandable without color alone.

Specify appropriate input type, autocomplete purpose, name, and disabled/read-only behavior. Group related controls with suitable semantics. Preserve user input when showing validation errors and explain how to correct them.

Test accessible names, descriptions, validation timing, error announcements, autofill, and password managers in real browser flows. App-level forms must also evaluate any relevant redundant-entry and accessible-authentication requirements.

Status: documentation preparation only; no fields are implemented or verified.
