# Versioning

Initial repository foundation: **0.1.0**. No registry release or GitHub release is created.

Use semantic versioning once public APIs exist:

- **Major:** breaking changes.
- **Minor:** new compatible functionality.
- **Patch:** fixes.

During 0.x development, APIs are provisional; explicitly document any breaking change and migration rather than implying stability. Do not release 1.0.0 until the agreed stability gates pass.

Changesets tooling is not installed or configured. Package versions currently mark workspace foundations, not usable published libraries. Final package scopes and license are still undecided.

Reference: [Semantic Versioning](https://semver.org/).
